### Filter

```
public string Filter { get; set; }
```

Allows filtering.

Supported syntax:

-   Filter expressions are made up of one or more restrictions.
-   Restrictions can be combined by `AND` or `OR` logical operators. A sequence of restrictions implicitly uses `AND`.
-   A restriction has the form of `{field} {operator} {value}`.
-   Supported fields/values for inspect jobs:
-   `state` - PENDING|RUNNING|CANCELED|FINISHED|FAILED
-   `inspected_storage` - DATASTORE|CLOUD\_STORAGE|BIGQUERY
-   `trigger_name` - The name of the trigger that created the job.
-   'end\_time\` - Corresponds to the time the job finished.
-   'start\_time\` - Corresponds to the time the job finished.
-   Supported fields for risk analysis jobs:
-   `state` - RUNNING|CANCELED|FINISHED|FAILED
-   'end\_time\` - Corresponds to the time the job finished.
-   'start\_time\` - Corresponds to the time the job finished.
-   The operator must be `=` or `!=`.

Examples:

-   inspected\_storage = cloud\_storage AND state = done
-   inspected\_storage = cloud\_storage OR inspected\_storage = bigquery
-   inspected\_storage = cloud\_storage AND (state = done OR state = canceled)
-   end\_time > &quot;2017-12-12T00:00:00+00:00&quot;

The length of this field should be no more than 500 characters.
