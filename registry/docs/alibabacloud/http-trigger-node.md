DataWorks provides HTTP trigger nodes that allow you to trigger the execution of an HTTP trigger node and its descendant nodes in a workflow from an external environment (such as a local environment or a cross-tenant environment) by calling an OpenAPI operation. This feature helps you implement local task triggering or meet task dependency execution requirements in cross-tenant environments.

## **Product introduction**

An HTTP trigger node is a special zero load node that lets you use the DataWorks OpenAPI [TriggerSchedulerTaskInstance](/help/en/dataworks/developer-reference/api-dataworks-public-2024-05-18-triggerschedulertaskinstance) to trigger the scheduling of this node and its descendant nodes.

The HTTP trigger node can trigger its descendant nodes only after the ancestor node of the HTTP trigger node is run as expected and the HTTP trigger node receives a scheduling instruction from the external scheduling system. For information about how to trigger an HTTP trigger node, see [Diagram of using a trigger node](#a83e2aa4a3lc1).

### **Diagram of using a trigger node**

HTTP trigger nodes are commonly used for communication between external environments and the DataWorks scheduling system.

![image](https://help-static-aliyun-doc.aliyuncs.com/assets/img/en-US/7676206671/CAEQUBiBgICewLua2RkiIDA3NzE5ODhkMTE3NjRiNzU5ODRlZDA5ODJkOGQwNmI15068292_20250507172052.667.svg)

**Diagram description**:

1.  In Data Development, create a workflow that contains an HTTP trigger node, configure the dependencies between nodes, and publish the workflow to Operation Center.
    
2.  The system automatically generates recurring instances based on the scheduling time. You can obtain the information about the HTTP trigger node (such as the node ID and trigger time) from these instances.
    
3.  Pass this information and use Java or Python code, or the API debugging page, to call the OpenAPI operation to trigger the node. To trigger only a specific instance and its subsequent workflow, set the `TriggerTime` parameter to a static field. To dynamically trigger all instances, set `TriggerTime` to a dynamic variable. After the HTTP trigger node receives and verifies the trigger command, it runs the subsequent nodes in sequence.
    

### **Trigger conditions**

The HTTP Trigger node can be run only if the following requirements are met:

-   The HTTP trigger node has generated a recurring instance. You can find this instance on the **Auto Triggered Instances** page in the Operation Center. Before the instance is successfully triggered by the [TriggerSchedulerTaskInstance](/help/en/dataworks/developer-reference/api-dataworks-public-2024-05-18-triggerschedulertaskinstance) API, the instance is in the **Waiting for Trigger** state. Its descendant nodes are blocked until the `TriggerSchedulerTaskInstance` API is called to trigger the HTTP trigger node. After the HTTP trigger node is run, its descendant nodes are run in sequence.
    
-   **All parent nodes that the HTTP trigger node depends on have been successfully executed** (the instances are in the success state).
    
-   The **scheduled time has arrived** for the recurring instance generated by the HTTP trigger node.
    
-   The scheduling resource group used by the HTTP trigger node has **sufficient resources** at the trigger time.
    
-   The HTTP trigger node is **not in a frozen state**.
    
-   Only HTTP trigger nodes in the **Waiting for Trigger state** can be triggered (nodes that have been successfully triggered will not execute again if triggered again).
    

## **Notes**

-   The HTTP trigger node can trigger its descendant nodes only after the ancestor node of the HTTP trigger node is run as expected and the HTTP trigger node receives a scheduling instruction from the external environment.
    
-   If the external environment sends a scheduling instruction in advance, but the ancestor node has not completed running, the HTTP trigger node will not trigger the descendant nodes. The system will retain the scheduling instruction from the external environment and trigger the descendant nodes through the HTTP trigger node after the ancestor node completes running.
    
    **Note**
    
    The trigger instruction from the external environment is retained for only 24 hours. If the ancestor node does not complete running within 24 hours, the trigger instruction will be lost, and the scheduling instruction sent by the external environment this time will become invalid.
    
-   After the current HTTP trigger node instance is successfully triggered and executed, it cannot be triggered a second time.
    

## **Prerequisites**

-   The RAM user that you want to use is added to your workspace.
    
    If you want to use a RAM user to develop tasks, you must add the RAM user to your workspace as a member and assign the **Develop** or **Workspace Administrator** role to the RAM user. The Workspace Administrator role has more permissions than necessary. Exercise caution when you assign the Workspace Administrator role. For more information about how to add a member and assign roles to the member, see [Add members to a workspace](/help/en/dataworks/user-guide/add-workspace-members-and-assign-roles-to-them).
    
-   A serverless resource group is associated with your workspace. For more information, see the topics in the [Use serverless resource groups](/help/en/dataworks/user-guide/using-serverless-resource-groups) directory.
    
-   Before developing an HTTP trigger node, you need to create the corresponding HTTP trigger node. For more information, see [Create a recurring task](/help/en/dataworks/user-guide/node-development-of-data-studio/#13d1ad442e1tc).
    

## **Limits**

-   The HTTP trigger node feature is only available in **DataWorks Enterprise Edition** and higher versions. For more information about DataWorks versions, see [Editions of DataWorks](/help/en/dataworks/user-guide/differences-among-dataworks-editions#concept-265336).
    
-   HTTP trigger nodes are only used for triggering tasks and cannot be used as compute-optimized tasks. You need to set the task node to be run as a descendant node of the HTTP trigger node to implement task triggering and execution.
    

## **Create an HTTP trigger node**

### **Create a new HTTP trigger node**

For information about how to create a new node, see [Create an HTTP trigger node](/help/en/dataworks/user-guide/node-development-of-data-studio/#13d1ad442e1tc).

### **Configure an HTTP trigger node**

After creating a new HTTP trigger node, configure the following parameters in **Scheduling** on the right side of the HTTP trigger node editing page. For more parameter configurations, see [Node scheduling](/help/en/dataworks/user-guide/node-scheduling/).

**Parameter**

**Description**

**Resource Group**

Select the serverless resource group that you have associated.

**Instance Generation Mode**

You can select **T+1 Next Day** or **Generate Immediately After Publishing**.

**Note**

-   The HTTP trigger node is a zero load node and does not require node content to be written.
    
-   When there is no node upstream of the HTTP trigger node, the default upstream node is the root node of the business flow.
    

### **Publish an HTTP trigger node**

1.  After completing the scheduling configuration, you can submit and publish the completed HTTP trigger node to the production environment. For more information, see [Publish nodes/workflows](/help/en/dataworks/user-guide/task-release/).
    
2.  The published tasks will run periodically according to your configured schedule. You can view the published recurring tasks in **Operation Center** > **Node O&M** > **Auto Triggered Node O&M** > **Auto Triggered Nodes** and perform O&M operations on the tasks. For more information, see [Get started with Operation Center](/help/en/dataworks/user-guide/getting-started-with-operation-center).
    

## **Trigger configuration in other scheduling environments**

When you configure triggers in external scheduling environments, you must configure the retrieved HTTP trigger node instance parameters in one of the following ways and call the `TriggerSchedulerTaskInstance` operation to trigger the HTTP trigger node.

### **Obtain HTTP trigger node instance parameters**

You can view and record HTTP instance parameter information in **Operation Center** based on the instance generation mode selected when [configuring the HTTP trigger node](#e1a0df1cf8oty).

**Note**

-   T+1 Next Day: You need to go to Operation Center the next day to view and record HTTP instance parameter information.
    
-   Generate Immediately After Publishing: You can immediately go to **Operation Center** to view and record HTTP instance parameter information.
    

1.  Go to the Operation Center page.
    
    Log on to the [DataWorks console](https://dataworks.console.aliyun.com/overview). In the top navigation bar, select the desired region. In the left-side navigation pane, choose **Data Development and O&M** > **Operation Center**. On the page that appears, select the desired workspace from the drop-down list and click **Go to Operation Center**.
    
2.  In the left navigation bar, click **Auto Triggered Node O&M** > **Auto Triggered Instances** to go to the **Auto Triggered Instances** page.
    
3.  Find the HTTP trigger node instance you created in the list and record the instance's **Task ID** and **Scheduled Time**.
    
    **Note**
    
    Hover your mouse over the name of the HTTP trigger node instance to view the instance's **Task ID.**
    

### **Method 1: Java invocation**

1.  Install the Java SDK. For more information, see [Use Alibaba Cloud SDK for Java in an IDE](/help/en/sdk/developer-reference/use-the-alibaba-cloud-sdk-through-the-ide).
    
    Specify the following Project Object Model (POM) configurations to use DataWorks SDK for Java:
    
    ```
    <dependency>
      <groupId>com.aliyun</groupId>
      <artifactId>dataworks_public20240518</artifactId>
      <version>6.2.0</version>
    </dependency>
    ```
    
2.  Sample code
    
    You can go to the [TriggerSchedulerTaskInstance debugging page](https://api.alibabacloud.com/api/dataworks-public/2024-05-18/TriggerSchedulerTaskInstance?spm=a2c4g.11186623.0.0.3ca116c6DgpmQn&RegionId=cn-hangzhou&tab=DEMO&lang=PYTHON&sdkStyle=dara&params={}) and view the complete Java example on the **SDK Sample** tab.
    
    ```
    package com.example.demo;
    
    import com.aliyun.dataworks_public20240518.Client;
    import com.aliyun.dataworks_public20240518.models.TriggerSchedulerTaskInstanceRequest;
    import com.aliyun.dataworks_public20240518.models.TriggerSchedulerTaskInstanceResponse;
    import com.aliyun.teaopenapi.models.Config;
    import com.aliyun.teautil.models.RuntimeOptions;
    
    import java.text.SimpleDateFormat;
    import java.util.Calendar;
    
    public class CrossTenantTriggerSchedulerTaskTo {
        // Method to trigger DataWorks node execution
        public static TriggerSchedulerTaskInstanceResponse runTriggerScheduler(com.aliyun.dataworks_public20240518.Client client, Long nodeId, String EnvType, Long TriggerTime) throws Exception {
            TriggerSchedulerTaskInstanceRequest request = new TriggerSchedulerTaskInstanceRequest(); // Create API request object
            request.setTaskId(nodeId); // Set the node ID to trigger
            request.setEnvType(EnvType); // Set the project environment
            request.setTriggerTime(TriggerTime); // Set the scheduled trigger time (millisecond timestamp)
            RuntimeOptions runtime = new RuntimeOptions(); // Initialize runtime configuration
            return client.triggerSchedulerTaskInstanceWithOptions(request, runtime); // Execute API call and return response
        }
    
        public static void main(String[] args) throws Exception {
            // Initialize node ID (example value)
            String nodeId = "xxx";
            // Initialize project environment (example value)
            String EnvTypeStr = "xxx";
            // Initialize scheduled time (example value)
            String cycTimeStr = "xxx";
            // Set service endpoint
            String endpoint = "xxx";
            // Convert string to Long type node ID
            Long nodeId1 = Long.parseLong(nodeId);
            // Output program usage instructions
            System.out.println("Usage: java -jar test-1.0-SNAPSHOT.jar nodeId EnvTypeStr cycTimeParam");
            // Parse scheduled time and convert to timestamp
            SimpleDateFormat sdft = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss");
            Calendar calendar = Calendar.getInstance();
            calendar.setTime(sdft.parse(cycTimeStr)); // Parse time string
            Long cycTime = calendar.getTimeInMillis(); // Get millisecond timestamp
            // Output debug information (timestamp)
            System.out.println("Scheduled timestamp: " + cycTime);
            // Initialize OpenAPI configuration object
            Config config = new Config();
            config.setAccessKeyId(System.getenv("ALIBABA_CLOUD_ACCESS_KEY_ID")); // Get AccessKey ID from environment variable
            config.setAccessKeySecret(System.getenv("ALIBABA_CLOUD_ACCESS_KEY_SECRET")); // Get AccessKey Secret from environment variable
            config.setEndpoint(endpoint);
            // Create Alibaba Cloud client instance
            Client client = new Client(config);
            // Execute node trigger operation
            TriggerSchedulerTaskInstanceResponse response = runTriggerScheduler(client, nodeId1,EnvTypeStr, cycTime);
            // Output API response result (JSON format)
            System.out.println(com.aliyun.teautil.Common.toJSONString(com.aliyun.teautil.Common.toMap(response)));
        }
    }
    ```
    
    Replace the relevant parameters in the above code with the actual values required for your business according to the following parameter descriptions.
    
    **Parameter**
    
    **Description**
    
    `nodeId`
    
    The **Task ID** of the HTTP trigger node obtained in the [Obtain HTTP trigger node instance parameters](#f353a1146dxrc) step.
    
    `EnvTypeStr`
    
    The project environment where the HTTP trigger node is located.
    
    Set the value to `**Prod**` for the production environment**.**
    
    Set the value to `**Dev**` for the development environment**.**
    
    `cycTimeStr`
    
    The **Scheduled Time** of the HTTP trigger node task that you obtained in the [Obtain HTTP trigger node instance parameters](#f353a1146dxrc) step. The time must be in the `yyyy-MM-dd HH:mm:ss` format.
    
    `endpoint`
    
    The endpoint of the workspace where the target HTTP trigger node is located. For more information, see [Alibaba Cloud OpenAPI Developer Service Endpoints](https://api.aliyun.com/product/dataworks-public).
    
    `ALIBABA_CLOUD_ACCESS_KEY_ID`
    
    The `AccessKey ID` of the Alibaba Cloud account to which the destination HTTP trigger node belongs.
    
    1.  Obtain an AccessKey pair.
        
        Log on to the [DataWorks console](https://workbench.data.aliyun.com/console). Move the pointer over your profile picture in the upper-right corner and click **AccessKey Management** to obtain the `AccessKey ID` and `AccessKey secret`.
        
    2.  Configure the environment variables. Configure the obtained AccessKey ID and AccessKey Secret as environment variables for the current environment. Later, you can dynamically obtain the AccessKey information by reading the environment variables, thereby avoiding the security risk of plaintext storage. For more information, see [Manage access credentials](/help/en/sdk/developer-reference/v2-manage-access-credentials).
        
    
    `ALIBABA_CLOUD_ACCESS_KEY_SECRET`
