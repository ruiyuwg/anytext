Tair (Redis OSS-compatible) provides performance monitoring metrics such as CPU utilization, memory usage, average latency, and queries per second (QPS). You can view the monitoring data of an instance during a specified time range within the last month. This helps you gain insights into the instance status and troubleshoot issues.

## Procedure

1.  Log on to the console and go to the [Instances](https://kvstore.console.alibabacloud.com/Redis/instance/cn-hangzhou) page. In the top navigation bar, select the region in which the instance that you want to manage resides. Then, find the instance and click the instance ID.
    
2.  In the left-side navigation pane, click **Performance Monitoring**.
    
3.  Perform the following operations based on the instance architecture:
    
    -   If the instance uses the master-replica architecture, you only need to pay attention to the metrics of the master node.
        
    -   If the instance uses the cluster or read/write splitting architecture, you have the following options:
        
        -   On the **All** tab, you can view the overall performance of the instance. Metrics on the All tab provide the aggregated monitoring data of replica nodes or read replicas. Different metrics use different aggregate methods such as taking the average or sum value. For example, the CPU utilization on the All tab is the average value of all replica nodes or read replicas.
            
        -   On the **Data Node** tab, you can view the monitoring metrics of each data node.
            
        
        If your instance has proxy nodes, you can view the overall performance of the proxy nodes on the **All** tab and view the metrics of each proxy node on the **Proxy Node** tab.
        
    
    **Note**
    
    -   You can view the monitoring data within the last month. In most cases, the maximum time range that you can specify for a query is three days.
        
    -   To ensure a smooth and efficient performance monitoring experience and prevent negative impacts on the instance operation, the granularity of data displayed in the trend charts varies based on the time range you select.
        
    -   For read/write splitting instances, the metric data of read replicas is not aggregated.
        
    

## FAQ

**After read/write splitting is enabled for an instance, why do read replicas have write QPS?**

The write QPS on read replicas is not directly generated by client-initiated write requests, but instead **represents the write operations that occur when the master node synchronizes data to the read replicas**.

**Why is the number of connections for a cluster architecture instance 0?**

In the proxy mode of the cluster architecture, the number of connections for data nodes is displayed as 0. The connections to data nodes are connections from proxy nodes to data nodes. These connections are reused and are typically internal connections, with an average value between 0 and 2. You need to check the client connections through the proxy node monitoring interface. You do not need to pay attention to the number of connections to data nodes.
