Agentic SOC in Security Center uses predefined or custom rules to analyze the context of multiple security alerts and aggregates them into complete incidents. It reconstructs attack chains and extracts malicious entities to help you quickly respond to and handle security risks in the cloud. This topic describes how to handle security incidents generated from Agentic SOC alerts.

## **Notes**

After you enable the Agentic SOC service, security incidents generated from Cloud Workload Protection Platform (CWPP) security alerts are migrated to Agentic SOC for processing. The handling process is the same as for security incidents generated by Agentic SOC. For more information, see [Overview of CWPP security](/help/en/security-center/user-guide/security-event-overview-cwpp) incidents.

## **Concepts of Agentic SOC security incidents**

### **Source of Agentic SOC security incidents**

Agentic SOC in Security Center generates security alerts based on predefined or custom rules. Agentic SOC then analyzes the context of these alerts and aggregates them into complete incidents.

**Note**

-   You can view Agentic SOC alert information on the **Aggregate and Analyze Alerts** and **Custom Alert Analysis** tabs of the **Agentic SOC** > **Alert** page.
    
-   For more information about how to configure predefined and custom rules, see [Rule management](/help/en/security-center/user-guide/detection-rules).
    

### **Agentic SOC security incident generation mechanism**

Agentic SOC security incidents are created by aggregating multiple related security alerts based on predefined or custom rules. This lets you quickly identify and respond to security threats. Security incidents are categorized into the following two types based on the source device of the alert:

-   Network-side: Agentic SOC focuses on malicious reconnaissance activities, such as scans or probing, and generates incidents from network-side alerts using predefined rules. This helps prevent attackers from probing for more user information.
    
-   Host-side: Agentic SOC uses graph computing technology to aggregate related host-side alerts, such as those with the same MD5 hash or parent process ID, into incidents. This helps you quickly locate the attack entry point and respond.
    

Not all alerts generate security incidents. An alert must meet the following conditions to trigger incident generation:

-   All host-side alerts generate security incidents. If a host-side alert has no related alerts, a single alert can generate an incident. Network-side alerts generate security incidents only if they hit an incident aggregation policy in a predefined or custom rule.
    
-   If an incident whitelisting rule is set, alerts that hit the rule do not generate incidents.
    
-   If only predefined rules are enabled, only alerts that match the **Graph Computing** and **Expert Rule** incident generation methods in the predefined rules generate incidents.
    

### **Incident** **retention period**

The **Security Incident** page only displays incidents from the last 180 days.

### **Objects handled in Agentic SOC security incidents**

You can handle security incidents by processing the aggregated alerts and the extracted alert entities.

#### **Agentic SOC security alerts**

Agentic SOC generates security alerts based on [predefined or custom rules](/help/en/security-center/user-guide/detection-rules). These alerts are then analyzed and aggregated into security incidents.

The alert aggregation rules are as follows:

-   For security incidents generated by graph computing, the maximum number of alerts is 2,000. For other incident generation methods, such as same-type aggregation, the maximum is 10,000.
    
-   For incidents in the Unhandled state, newly generated alerts can continue to be aggregated into the incident.
    
-   For incidents in the Handling, Handled, or Failed state, newly generated alerts are not aggregated into the existing incident. Instead, a new incident is created in the Unhandled state.
    

#### **Entities**

In a security incident, an entity is a specific object or actor associated with the incident. Security Center extracts and aggregates entities from security alerts. Security Center classifies entities as either malicious or non-malicious based on whether they have malicious tags.
