This topic provides answers to some commonly asked questions about access control over Dynamic Content Delivery Network (DCDN) resources.

## **When I configure an IP address blacklist or whitelist, the number of IP addresses is limited. Is a CIDR block considered one IP address or multiple IP addresses?**

Dynamic Content Delivery Network (DCDN) allows you to add up to about 700 IPv6 addresses and 2,000 IPv4 addresses to an IP address blacklist or whitelist.

A CIDR block is considered one IP address.

## **Why can I still use an IP address in the IP address blacklist to request resources?**

DCDN cannot restrict clients from initiating requests. After you configure an IP address blacklist, DCDN returns the HTTP 403 status code for requests from IP addresses in the blacklist and records the requests in DCDN logs. For information about how to view logs, see [Download offline logs](/help/en/cdn/user-guide/download-logs#task-187634).

## **How do I retrieve the originating IP addresses of clients?**

If you use DCDN, you can retrieve the originating IP addresses of clients from the X-Forwarded-For header. For more information, see [Retrieve the originating IP addresses of clients](/help/en/waf/web-application-firewall-2-0/user-guide/retrieve-the-originating-ip-addresses-of-clients).

## **Can I obtain the IP addresses of POPs that I want to add to the origin whitelist?**

You can [submit a ticket](https://smartservice.console.alibabacloud.com/?spm=5176.2020520001.aliyun_topbar.18.dbd44bd3e4f845#/ticket/createIndex) to apply for the permission to call the [DescribeDcdnL2Ips](/help/en/edge-security-acceleration/dcdn/developer-reference/api-dcdn-2018-01-15-describedcdnl2ips) operation and obtain the IP addresses of points of presence (POPs).

## **What do I do if HTTP status code 403 is returned due to URL signing exceptions when I access** DCDN**\-accelerated resources?**

URL signing is used to protect resources on origin servers from unauthorized downloads. After you enable the URL signing feature of DCDN, if HTTP status code 403 is returned when you access DCDN\-accelerated resources, you can view detailed error information in the **Response Header** by using the developer tool of the browser. The following section describes the errors:

### **Error message**: X-Tengine-Error:denied by req auth: no url arg auth\_key

-   **Cause**: The URL signing feature of DCDN is enabled, but the request URL does not contain authentication parameters.
    
-   **Solution**: Correctly use URL signing by following instructions in [Configure URL signing](/help/en/edge-security-acceleration/dcdn/user-guide/configure-url-signing). If you no longer need it, disable the feature on the [DCDN console](https://dcdn.console.alibabacloud.com/overview).
    

### **Error message**: X-Tengine-Error: denied by req auth: expired timestamp

-   **Cause**: The URL signing feature of DCDN is enabled and the URL contains authentication parameters, but the authentication parameters expired.
    
-   **Solution**: Regenerate a signed URL by following instructions in [Configure URL signing](/help/en/edge-security-acceleration/dcdn/user-guide/configure-url-signing).
    

### **Error message**: X-Tengine-Error: denied by req auth: invalid md5hash

-   **Cause:** The MD5 value in signing parameters is incorrectly calculated.
    
-   **Solution:** We recommend that you generate an encrypted URL in the DCDN console and compare the URL with the one that is generated by using your own signing code. For more information, see [URL signing examples](/help/en/edge-security-acceleration/dcdn/user-guide/url-signing-examples).![image.png](https://help-static-aliyun-doc.aliyuncs.com/assets/img/en-US/1543366671/p753649.png)
    

## **Can URL signing and remote authentication be enabled at the same time?**

Yes, you can enable both URL signing and remote authentication. Requests are authenticated first by URL signing and then by remote authentication.

## **Can a remote authentication server use a private network address?**

No, it cannot. The remote authentication server must be configured with a public network address.

## **Why does DCDN grant access when an authentication server returns a status code that is neither a success nor a failure code?**

DCDN grants user requests by default if the authentication server returns a status code that is not a success or failure code. This default behavior prevents blocking all user requests. For example, if you set the success status code to 200 and the authentication server returns 201, DCDN grants the user request.

You can set the **Allow Other Status Codes** parameter in the console to specify whether to grant access for other status codes from the authentication server.

## **Does DCDN allow all requests if a remote authentication server fails or goes down?**

No, it does not. When a remote authentication server fails or goes down, the connection from DCDN may time out. DCDN then uses the setting of the **Action on Timeout** parameter to determine whether to allow the request.
