ApsaraDB for MongoDB allows you to configure manual primary/secondary failover, so that you can perform real-time disaster recovery drills and verify the exception handling capabilities of clients. If your instance is deployed in multiple zones, you can also configure a manual failover to allow applications to connect to the nearest node.

You can configure manual primary/secondary failover for replica set and sharded cluster instances, but not for standalone instances due to their single-node architecture. For more information about how to configure manual primary/secondary failover, see [Trigger a primary/secondary failover for a replica set instance](/help/en/mongodb/user-guide/trigger-a-primary-or-secondary-failover-for-a-replica-set-instance#task-phh-vjh-kfb) and [Configure a primary/secondary failover for a sharded cluster instance](/help/en/mongodb/user-guide/configure-a-primary-or-secondary-failover-for-a-sharded-cluster-instance#concept-wcc-cc5-cgb).
