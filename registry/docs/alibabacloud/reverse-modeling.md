If you have numerous physical tables in a compute engine and want to manage them in DataWorks Data Modeling, use the reverse modeling feature. It imports existing physical tables into the DataWorks dimensional modeling framework, saving significant effort by eliminating manual model creation. This topic describes how to perform reverse modeling.

## Prerequisites

-   You have a large number of physical tables in a compute engine, and you have created a data source for that engine in the target DataWorks workspace. For more information about how to create a data source, see [Manage data sources](/help/en/dataworks/user-guide/add-and-manage-data-sources/).
    
-   You have defined data warehouse layers to classify the models. For more information, see [Define data warehouse layers](/help/en/dataworks/user-guide/data-warehouse-layering#a08bfd8742cky).
    
-   The Common Layer processes and integrates public data from the source layer, establishes unified metrics and dimensions, and builds reusable detailed fact data and summary data for analysis and statistics. The Application Layer retrieves the processed and integrated data from the Common Layer based on actual application requirements to perform personalized data statistics for specific application scenarios or designated products.
    
    Models that you create can be assigned to the **Common Layer** or the **Application Layer**. You must complete the following preparations separately for each layer:
    
    -   **Common Layer**:
        
        -   You have created a data domain to define the business scope of the data in the model. For more information, see [Data domains](/help/en/dataworks/user-guide/business-planning#0325b13dbd1hy).
            
        -   You have created a business process to define the specific business activity that the model analyzes. For more information, see [Business processes](/help/en/dataworks/user-guide/business-planning#88bfddccc3ibq).
            
    -   **Application Layer**:
        
        -   You have created a data mart to classify data for a specific application scenario or product. For more information, see [Data marts](/help/en/dataworks/user-guide/business-planning#e6023f7defrj3).
            
        -   You have created a subject area to define the specific business subject that the model covers. For more information, see [Subject areas](/help/en/dataworks/user-guide/business-planning#eb4fd0bd6ecbk).
            

## Limitations

This feature supports only tables in the production environments of MaxCompute and E-MapReduce (EMR) Hive compute engines.

## How it works

Reverse modeling imports existing physical tables from a big data compute engine into the dimensional modeling module of DataWorks. The process is as follows:![逆向建模流程](https://help-static-aliyun-doc.aliyuncs.com/assets/img/en-US/5837037361/p348064.png)

1.  Configure a reverse modeling policy.
    
    -   Scope: Determine which tables to import by specifying the workspace and compute engine instance. You can match tables by name or keyword. DataWorks then uses these tables to generate models.
        
        This process requires you to specify the Workspace and Compute Engine Instance for the table, and whether to match the table name by using an exact name or a keyword. The matched tables are then reverse-engineered to generate corresponding models.
        
    -   Modeling rules: Define the target data layer and the naming convention for the generated models.
        
        You can use a table name checker or define a custom convention to standardize model names within the same layer. Consistent naming helps identify the business type and data granularity of a model from its name. For more information about table name checkers, see [Configure data warehouse layer checkers](/help/en/dataworks/user-guide/data-warehouse-layering#ac1f1059e2xm8) and [Use checkers](/help/en/dataworks/user-guide/data-warehouse-layering#8a4cee1c78dzu).
        
    -   Execution method: Choose whether to create all target models from scratch (full update) or only the models that do not already exist in the dimensional modeling module (incremental update).
        
    
    **Note**
    
    Plan your policy carefully, as it cannot be modified after it is created and used to generate models.
    
    For more information, see [Configure a reverse modeling policy](#step-78q-t3y-hld).
    
2.  Parse tables and match models.
    
    DataWorks parses the tables and identifies the models to be created based on your policy.
    
3.  Confirm model information.
    
    The initial models generated by DataWorks may require adjustments. You need to review and modify model information, such as the **Data Domain** and **Business Process**, to align with your business requirements. For more information, see [Confirm model information](#step-aib-1p9-lj0).
    
4.  Generate final models.
    
    After the modeling task is complete, you can view the information and status of the generated models. If a model fails to be created, you can view the error message to quickly identify and resolve the issue.
    
    **Note**
    
    -   Successfully generated models are already materialized in the corresponding compute engine. You do not need to publish them again.
        
    -   Successfully generated models are stored in the dimensional modeling module. You can go to the Dimensional Modeling page to view and manage them. For more information, see [Publish and manage a table](/help/en/dataworks/user-guide/publish-and-materialize-a-table#task-2090839).
        
    

## Procedures

1.  Go to the **Reverse Modeling** page.
    
    1.  Log on to the [DataWorks console](https://dataworks.console.aliyun.com/overview). In the top navigation bar, select the desired region. In the left-side navigation pane, choose **Data Development and O&M** > **Data Modeling**. On the page that appears, select the desired workspace from the drop-down list and click **Go to Data Modeling**.
        
    2.  In the top navigation bar of the **Data Modeling** page, click **Dimensional Modeling** to go to the **Dimensional Modeling** page.
        
    3.  In the navigation pane on the left of the **Dimensional Modeling** page, click **Reverse Modeling** to go to the **Reverse Modeling** page.
        
2.  Start a modeling task.
    
    -   If you are using this feature for the first time, click **Reverse Modeling****Start Now** on the Reverse Modeling page.
        
    -   If you have used this feature before, click **Modeling Tasks****Start Reverse Modeling** in the upper-right corner of the Modeling Tasks list.
        
    
3.  Configure a reverse modeling policy.
    
    **Note**
    
    Plan your policy carefully, as it cannot be modified after it is created and used to generate models.
    
    1.  Configure the policy information.
        
        ![逆向策略](https://help-static-aliyun-doc.aliyuncs.com/assets/img/en-US/6391107961/p347058.png)
        
        **Parameter**
        
        **Description**
        
        **Workspace**
        
        Select the DataWorks workspace where the source tables are located.
        
        **Note**
        
        You can select only a DataWorks workspace to which your account belongs. To select a different workspace, you must be added as a member to that workspace. For more information, see [Manage permissions on modules at the workspace level](/help/en/dataworks/user-guide/manage-permissions-on-workspace-level-services#task-2059693).
        
        **Compute Engine Type**
        
        Reverse modeling currently supports only physical tables in the production environments of MaxCompute and E-MapReduce (EMR) Hive compute engines.
        
        **Compute Engine Instance**
        
        Select the compute engine instance where the source tables are located.
        
        **Table Name Matching Rule**
        
        Select a method to match tables in the target compute engine. DataWorks then imports the matched tables.
        
        -   **Fuzzy Match**: Enter a keyword to match all tables whose names contain the keyword.
            
        -   **Exact Match**: Enter the full and exact name of a table.
            
        
        **Note**
        
        -   Separate multiple table names with semicolons (`;`). Do not add spaces after the semicolons.
            
        -   If no tables are matched, the reverse modeling task fails and generates no models.
            
        
        **Data Layer of Model After Reverse Modeling**
        
        -   **Common Layer**: Select this layer to create fact tables, dimension tables, and aggregate tables.
            
        -   **Application Layer**: Select this layer to create application tables and dimension tables.
            
        
        **Table Naming Rule**
        
        This rule parses the names of the tables matched by the **Table Name Matching Rule**, standardizes the names of the generated models, and assigns them to the appropriate data warehouse layer.
        
        -   **Parsing rules**
            
            -   Parse the matched table name and the number of underscores.
                
                A table name can contain a maximum of nine underscores, and the segments between them can be configured to specify information such as **Business Process**, **Data Domain**, and **Custom**.
                
            -   If the table name contains a recognized data layer prefix, the system assigns the generated model to that layer.
                
            
            **Note**
            
            If a corresponding **Data Domain**, **Business Process**, or other layer information is not found in the table name, the layer for that model is left empty. You can assign the model to a layer when you **Confirm Model Information**.
            
        -   **Parsing methods**
            
            -   **Table Name Checker**: Select a pre-configured checker to parse the matched table names. For more information about how to create a checker, see [Configure data warehouse layer checkers](/help/en/dataworks/user-guide/data-warehouse-layering#ac1f1059e2xm8) and [Use checkers](/help/en/dataworks/user-guide/data-warehouse-layering#8a4cee1c78dzu).
                
            -   **Custom Rule**: Parse the matched table names by creating a custom combination of **Business Process**, **Data Domain**, **Business Category**, and **Custom** content.
                
        
        **Execution Method**
        
        Select a creation method:
        
        -   **Full Update**: DataWorks imports all matched tables into the dimensional modeling module.
            
            Choose this method if you want to regenerate models for all matched tables from scratch.
            
            **Note**
            
            If a model for a matched table already exists, **Full Update** deletes the existing model and creates a new one.
            
        -   **Incremental Update**: DataWorks performs the following steps:
            
            1.  Identifies and filters out tables that already have a corresponding model in the dimensional modeling module.
                
            2.  Imports only the matched tables that do not have an existing model.
                
            
            Choose this method if you know that some models already exist and do not need to be re-created.
            
        
    2.  Click **Create Model** to parse the tables based on the policy.
        
4.  Confirm model information.
    
    1.  Confirm the model information.
        
        DataWorks generates initial models based on your policy. You can adjust the **Table Type** and assign the models to the correct **Data Layer**, **Data Domain**, and other attributes as needed. You can also delete tables that you do not want to model.![确认模型信息](https://help-static-aliyun-doc.aliyuncs.com/assets/img/en-US/5227427361/p347060.png)
        
    2.  Click **Generate Model** to create the models.
        
5.  View the modeling results.
    
    Once the models are generated, you can view a count of successfully created models by type. For failed tasks, you can view detailed information and click **Error Logs** to quickly identify and resolve the issue.
    
    **Note**
    
    -   Successfully generated models are already materialized in the corresponding compute engine. You do not need to publish them again.
        
    -   Successfully generated models are stored in the dimensional modeling module. You can go to the Dimensional Modeling page to view and manage them. For more information, see [Publish and manage a table](/help/en/dataworks/user-guide/publish-and-materialize-a-table#task-2090839).
        
    
    ![生成模型](https://help-static-aliyun-doc.aliyuncs.com/assets/img/en-US/5227427361/p348029.png)
    

## View modeling tasks

On the **Reverse Modeling** > **Modeling Tasks** page, you can view the details and operation logs of your created tasks.![查看建模列表](https://help-static-aliyun-doc.aliyuncs.com/assets/img/en-US/5227427361/p348037.png)

**Section**

**Description**

1

In this section, you can filter reverse modeling tasks by **Task ID**, **Operated By**, or **Operation Date**.

2

This section displays the details of each task, including the reverse modeling rules and results.

-   For a completed task, click **View Logs** to see its logs.
    
-   For an incomplete task, click **View Task** to return to the task details page and continue the process.
    

## Next steps

After you complete the reverse modeling task, you can perform the following operations:

-   Go to the model management tree on the Dimensional Modeling page to view the created models. For more information, see [Publish and materialize a table](/help/en/dataworks/user-guide/publish-and-materialize-a-table#section-o6w-mm9-a21).
    
-   Go to the DataStudio page to perform tasks in DataStudio. For an introduction to the features of DataStudio, see [Introduction to DataStudio features](/help/en/dataworks/user-guide/features-on-the-datastudio-page#concept-zcr-5yd-p2b).
